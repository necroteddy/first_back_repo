Zero trust security — never trust, always verify

Zero trust is not a product you buy or a configuration you apply once. It is a security philosophy that has become the defining approach for organisations that have recognised a fundamental truth: the traditional model of trusting everything inside the network is no longer viable.

CyberSense Editorial  ·  6 min read

The traditional security model assumed a trusted interior and an untrusted exterior. Build strong walls around the network, and everything inside can be trusted. This model worked when staff worked from a single office, on company-owned devices, connecting to on-premise systems. It has not worked for some years — and for most businesses, it is now entirely obsolete.

Staff work from home, from cafés, from client sites. They use personal devices, cloud services, and applications that live entirely outside the corporate network. An attacker who compromises any one of these entry points — a phishing email, a stolen credential, a compromised home router — finds themselves "inside" a network that then trusts them implicitly. Zero trust is the answer to this problem: stop trusting location, and start verifying identity, device, and context for every access request.

The three core principles of zero trust

Principle 01

Verify explicitly

Every access request — regardless of where it comes from, who it appears to be from, or what network it is on — must be authenticated and authorised. Being on the corporate network, using a familiar device, or connecting from a known location does not automatically grant access. Every request is verified every time, using all available signals: identity, device health, location, time, and behaviour.

Principle 02

Use least privilege access

Access is granted to the minimum necessary for the specific task at hand — not to the entire network, not to all data, not permanently. Just-in-time and just-enough access, scoped to what is actually needed, means that a compromised account has a strictly limited blast radius.

Principle 03

Assume breach

Design and operate as if a breach has already occurred or will occur. Segment access so that a compromised account or device cannot move freely. Monitor all activity for anomalies. Have containment and response plans ready. Do not depend on the assumption that the perimeter will hold — because it will not always hold.

Zero trust is a journey, not a product

Zero trust is frequently marketed as a technology you can buy and deploy. It is not. It is a set of principles that you implement progressively through a combination of existing tools, configuration changes, and architectural decisions. A business that has never implemented zero trust does not start by buying a zero trust platform — it starts by implementing the controls that zero trust principles demand.

The good news is that if you have been following good security practice — enabling MFA, applying least privilege, keeping software patched, monitoring access — you have already begun implementing zero trust principles, even if you have never called it that.

NCSC's zero trust architecture guidance explicitly states that zero trust is not about buying new tools — it is about applying a set of principles. Most organisations can make significant progress toward zero trust using tools they already have, configured more carefully than before.

Practical zero trust controls for any business

Zero trust does not require enterprise-grade infrastructure to begin. These controls represent the most accessible and highest-impact starting points for any business.

  • Strong MFA on every account — the most fundamental zero trust control. Verifying identity explicitly, with a second factor, before granting any access. Start here.
  • Conditional access policies — grant access based on context, not just credentials. Require MFA from unfamiliar locations. Block access from non-compliant devices. Restrict access to sensitive applications to managed devices only. Microsoft Entra ID and Google Workspace both support conditional access.
  • Device compliance enforcement — before a device can access business systems, verify it meets defined security requirements: up-to-date OS, endpoint protection installed, disk encryption enabled. MDM platforms enforce this automatically.
  • Least privilege access controls — every user, every service account, every application has only the minimum access its role requires. No broad admin rights, no excessive sharing permissions, no legacy access that was never revoked.
  • Network segmentation — divide the network so that a compromised device in one segment cannot freely reach systems in another. The principle of assume breach demands that lateral movement is restricted.
  • Continuous monitoring and anomaly detection — log all access, monitor for unusual patterns, and alert on deviations from normal behaviour. A zero trust architecture assumes breach — monitoring is how you detect it.

Zero Trust Network Access — the modern replacement for VPN

Traditional VPNs grant network-level access — a connected user can reach everything on the network segment. Zero Trust Network Access (ZTNA) replaces this with application-level access: a user is granted access to specific applications, not the network, and each access request is verified independently.

Cloudflare Zero Trust has a generous free tier. Microsoft Entra Private Access and Zscaler Private Access are enterprise-grade options. For businesses with significant remote workforces or sensitive internal applications, ZTNA provides meaningfully stronger security than a traditional VPN at comparable or lower cost.

⚠ Zero trust does not mean zero convenience

A common objection to zero trust is that it will create friction for staff — requiring additional authentication steps, blocking access from personal devices, and adding verification to previously seamless workflows. Well-implemented zero trust minimises this friction through intelligent policy: trusted devices on known networks authenticate seamlessly, while unfamiliar conditions trigger additional verification. The goal is to make security invisible when conditions are normal and visible only when something is unusual.

Where to start

The most common barrier to zero trust adoption is not cost or complexity — it is not knowing where to begin. The answer is the same for almost every business: start with identity.

Enable MFA on every account. Configure conditional access policies to enforce device compliance and restrict access based on risk signals. Apply least privilege to all roles. These three steps implement the core of zero trust's "verify explicitly" and "least privilege access" principles — and they are achievable for any business with a Microsoft 365 or Google Workspace subscription.

Zero trust checklist

  • MFA enabled on every account — the foundation of "verify explicitly"
  • Conditional access policies configured — access based on identity, device, location, and risk
  • Device compliance enforced before business system access is granted
  • Least privilege applied to all users, service accounts, and applications
  • Network segmentation in place — lateral movement restricted
  • Access logging enabled on all systems — anomalies monitored and alerted
  • Just-in-time access used for privileged operations where possible
  • ZTNA evaluated as a replacement or supplement to traditional VPN
  • Assume breach mindset applied — containment and response plans ready
  • Zero trust principles applied to suppliers and third parties — not just internal users

Zero trust is not a destination — it is a direction. No organisation fully achieves it, and the threat landscape it responds to never stops evolving. But every step toward it — every additional verification, every least-privilege configuration, every assumption that the perimeter may already be breached — makes the business meaningfully harder to attack and meaningfully faster to recover from when an attack succeeds.
