Cloud security — protecting your data where your business actually runs

Most businesses now run primarily in the cloud — email, documents, finance, CRM, HR. The cloud provides extraordinary convenience and capability. It also introduces security responsibilities that many businesses have never fully understood or addressed.

CyberSense Editorial  ·  6 min read

The shift to cloud services is one of the most significant changes in how businesses operate over the past decade. For most small businesses, the cloud is no longer a supplement to on-premise infrastructure — it is the infrastructure. Microsoft 365, Google Workspace, Xero, Salesforce, Dropbox, Slack — the average small business uses dozens of cloud services, each holding data that is essential to operations.

Cloud security is not the provider's problem alone. Every major cloud provider makes clear that security is a shared responsibility — the provider secures the infrastructure; the customer is responsible for their data, their user accounts, and their configuration choices. Most breaches involving cloud services are not caused by failures in the cloud infrastructure. They are caused by the customer's misconfiguration, weak credentials, or inadequate access controls.

The shared responsibility model — what you own

Every cloud provider operates a shared responsibility model. The exact division varies by service type, but the principle is consistent: the provider is responsible for the security of the cloud — the infrastructure, the physical data centres, the underlying platform. The customer is responsible for security in the cloud — the data, the identities, the access configuration, and the applications built on top.

For SaaS services like Microsoft 365 or Google Workspace, your responsibilities are primarily around identity and access management, data classification, and configuration of the security features the platform provides. For IaaS services like AWS EC2 or Azure VMs, your responsibilities extend to the operating system, the applications running on it, and the network configuration.

The shared responsibility model does not mean the provider takes care of security. It means the provider takes care of their part and you take care of yours. Assuming the provider handles everything is one of the most common and most expensive misunderstandings in cloud security.

The most common cloud security failures

Risk 01

Publicly accessible storage

Cloud storage buckets — AWS S3, Azure Blob Storage, Google Cloud Storage — misconfigured as publicly accessible have exposed sensitive data in thousands of breaches. A single configuration checkbox, left on default or changed without understanding, can make a company's entire document store readable by anyone on the internet.

Risk 02

Weak or no MFA on cloud accounts

Cloud service accounts without MFA are compromised through credential stuffing, phishing, and brute force constantly. A compromised Microsoft 365 or Google Workspace account gives an attacker access to email, documents, calendar, contacts, and often connected applications — the core of most businesses.

Risk 03

Over-permissive IAM policies

Cloud identity and access management policies that grant more access than necessary — particularly admin or full-access roles assigned broadly — mean that a single compromised account can reach everything. Least privilege in cloud IAM is just as important as in any other context.

Risk 04

Credentials in code and repositories

API keys, database passwords, and cloud access credentials committed to code repositories — particularly public GitHub repositories — are harvested within minutes by automated scanners. This remains one of the most prevalent and entirely preventable causes of cloud data breaches.

Securing your SaaS applications

For most small businesses, the most important cloud security work is in their SaaS applications — Microsoft 365, Google Workspace, and the dozens of other tools the team uses every day. These platforms include powerful security capabilities that many businesses have never enabled.

  • Enable MFA on every account — the single most important control. Microsoft and Google both support conditional access policies that can enforce MFA based on device, location, and risk level.
  • Review third-party app connections — every application that asks for permission to connect to your Microsoft 365 or Google Workspace account receives some level of access to your data. Review connected applications regularly and revoke those that are no longer used or whose permissions are excessive.
  • Configure data loss prevention policies — both Microsoft and Google offer DLP features that can detect and block sensitive data being shared externally without authorisation.
  • Enable audit logging — ensure audit logs are enabled and retained for an appropriate period. Logs are essential for detecting compromise and for incident investigation.
  • Review sharing settings — check what your default sharing settings are for documents and drives. "Anyone with the link" is convenient but creates risk that is difficult to audit or control.
⚠ Check third-party app permissions now

In Microsoft 365: admin centre → Azure Active Directory → Enterprise Applications. In Google Workspace: admin console → Security → API controls → Manage third-party app access. You are likely to find applications that have been granted access and are no longer used, or whose permissions are broader than their function requires. Revoke access for anything unnecessary.

Securing cloud infrastructure (IaaS)

If your business uses cloud infrastructure — virtual machines, databases, storage buckets, or containers on AWS, Azure, or GCP — the security responsibilities extend significantly further than for SaaS. The most critical controls are configuration management, identity and access management, and network security.

  • Never use root or administrator accounts for day-to-day operations — create named IAM users or roles with the minimum necessary permissions for each task
  • Audit storage bucket permissions — run automated checks to identify any storage that is publicly accessible; there should be no public buckets unless there is a specific, deliberate reason
  • Enable cloud security posture management — AWS Security Hub, Azure Security Centre, and Google Security Command Centre provide free or low-cost automated checks of your configuration against security best practices
  • Encrypt data at rest and in transit — enable server-side encryption on all storage; ensure all connections use TLS; manage encryption keys appropriately
  • Enable CloudTrail, Azure Monitor, or Cloud Audit Logs — comprehensive logging of all API calls and configuration changes is essential for detecting and investigating incidents

AWS Security Hub, Azure Security Centre, and Google Security Command Centre each provide a free security score and a prioritised list of misconfigurations across your cloud environment. If you run cloud infrastructure and have not activated these tools, doing so is one of the highest-value, lowest-effort cloud security improvements available.

Cloud security checklist

  • MFA enabled on all cloud service accounts — Microsoft 365, Google Workspace, AWS, and every other platform
  • Third-party app connections reviewed — unnecessary or excessive permissions revoked
  • Document and drive sharing settings reviewed — default sharing restricted appropriately
  • Audit logging enabled on all cloud platforms and retained for investigation
  • Storage buckets audited — no unintentional public access
  • IAM roles and permissions reviewed — least privilege applied
  • Credentials and API keys not stored in code or repositories
  • Cloud security posture tool activated — AWS Security Hub, Azure Security Centre, or GCP SCC
  • Data encrypted at rest and in transit on all cloud storage
  • Leaver offboarding includes revocation of all cloud service access
  • Shared responsibility model understood — your obligations clearly defined for each platform

The cloud has transformed what small businesses can do with limited resources. It has also transformed where data lives, who can access it, and what can go wrong. The businesses that use the cloud most safely are those that understand that convenience and security are not mutually exclusive — they are a configuration choice.
