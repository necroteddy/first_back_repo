Patch management — why keeping software updated is your most powerful defence

The majority of successful cyberattacks exploit vulnerabilities that already had patches available. Attackers do not wait for defences to improve — they scan for businesses running outdated software and strike before the window closes. Patching is not maintenance. It is defence.

CyberSense Editorial  ·  6 min read

In the aftermath of almost every major data breach, the same finding appears: a known vulnerability, a patch that was available, and a system that had not been updated. The WannaCry ransomware attack in 2017 — which caused billions in damage globally — exploited a Windows vulnerability for which a patch had been available for two months. The organisations that were protected had simply applied it. The organisations that were compromised had not.

Patch management is the practice of ensuring that software and firmware updates are applied promptly, consistently, and verifiably across every device and system in a business. It is unglamorous, repetitive, and frequently deprioritised. It is also one of the most effective security controls available — and one of the five controls required by the NCSC's Cyber Essentials framework.

How the window of exposure works

When a vulnerability is publicly disclosed, the race begins. Security researchers and attackers both analyse the patch to understand what it fixes — and therefore what the underlying vulnerability is. Within days, proof-of-concept exploit code is typically available. Within two weeks, active exploitation in the wild is common for high-severity vulnerabilities.

Day 0

Vulnerability disclosed and patch released

The vendor publishes the patch and a security advisory. The details are public. Attackers begin analysis.

Day 1–3

Proof-of-concept code appears

Security researchers — and attackers — reverse-engineer the patch to understand the vulnerability. Working exploit code appears on public forums and dark web markets.

Day 7–14

Active exploitation begins at scale

Automated scanning tools probe the internet for vulnerable systems. Businesses that have not patched become easy targets. The window is closing fast.

Day 30+

Vulnerability incorporated into attack toolkits

The vulnerability is packaged into automated attack frameworks used by less sophisticated attackers. An unpatched system months later is still at serious risk.

What needs to be patched — and in what order

Everything running software needs to be patched — operating systems, applications, browsers, plugins, firmware on routers and network devices, and cloud-hosted software where updates are the customer's responsibility. The practical challenge for most businesses is not knowing this but doing it consistently across every device.

Priority order for patching:

  • Critical severity patches for internet-facing systems — apply within 24–48 hours. Web servers, VPNs, firewalls, and email gateways that are directly reachable from the internet are the highest priority targets for attackers.
  • Critical severity patches for internal systems — apply within 7 days. Operating systems, browsers, and commonly exploited applications like Office and PDF readers.
  • High severity patches — apply within 14 days.
  • Medium and low severity patches — include in regular monthly patching cycles.

The NCSC's Cyber Essentials certification requires that all software is patched within 14 days of a security update being released, and that unsupported software is removed. These targets are achievable for most small businesses and represent a significant reduction in exploitable attack surface.

Automating patch management

Manual patching does not scale and is reliably inconsistent. The most effective patch management programmes automate the deployment of updates across all devices, reducing the human effort required and eliminating the gaps that occur when updates are left to individuals to apply at their discretion.

  • Windows Update for Business — configurable through Microsoft Intune or Group Policy to automatically apply updates on a defined schedule, with reporting on compliance across all enrolled devices
  • Apple MDM with Software Update policies — forces macOS and iOS updates through an MDM platform, ensuring all Apple devices remain current
  • Third-party patching tools — Patch My PC, NinjaRMM, and similar tools automate patching of third-party applications (browsers, Adobe products, Zoom, etc.) that Windows Update does not cover
  • Cloud software — most SaaS applications update automatically; verify that auto-update is not disabled and that you are on a supported version
⚠ Browsers and plugins are consistently overlooked

Operating system patches receive the most attention but browsers — Chrome, Firefox, Edge, Safari — and their extensions are among the most frequently exploited software in targeted attacks. Browsers should be configured to update automatically and silently. Check right now whether every browser on your business devices is on the current version. In Chrome, go to Help → About Google Chrome. In Edge, go to Help and Feedback → About Microsoft Edge.

Handling legacy and unsupported software

Unsupported software — software for which the vendor no longer releases security patches — is a persistent risk that many businesses carry without fully understanding the implications. Windows 10 reached end of support in October 2025. Many businesses still run older versions of Office, custom line-of-business applications on outdated platforms, or specialist software that has not been updated for years.

Every piece of unsupported software is a vulnerability that cannot be patched. The options are: upgrade to a supported version; isolate the system from the internet and from sensitive data; or accept the risk explicitly and consciously rather than by default. The NCSC's Cyber Essentials certification requires the removal of unsupported software.

If your business runs software that cannot be updated — because the vendor no longer supports it, or because updates break a critical workflow — that software should be isolated on a network segment with no internet access and no connection to systems holding sensitive data. Isolation does not fix the vulnerability, but it significantly limits the damage if it is exploited.

Patch management checklist

  • Automatic updates enabled on all operating systems — Windows, macOS, iOS, Android
  • Browsers configured to update automatically on all devices
  • Critical patches applied within 14 days — internet-facing systems within 48 hours
  • Third-party application patching in place — browsers, Office, PDF readers, Zoom
  • MDM used to enforce and verify update compliance across all enrolled devices
  • Firmware updates applied on routers, firewalls, and network devices
  • Unsupported software identified — upgraded, isolated, or risk explicitly accepted
  • Patch compliance reported monthly — gaps investigated and remediated
  • End-of-support dates tracked for all key software — upgrade plans in place

Patching is the unglamorous foundation of cybersecurity — less interesting than AI-powered threat detection, less visible than a new security tool, and less exciting than a post-incident review. It is also consistently the most effective preventive control available. The businesses that patch promptly and completely are the ones that are not in next year's breach statistics.
